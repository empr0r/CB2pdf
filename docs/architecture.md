# Architecture and contracts

`config.py` owns immutable validated conversion/resource policies. `models.py` defines members, image metadata, page results, jobs and conversion outcomes. `errors.py` distinguishes archive, image, dependency, resource, PDF, collision, cancellation and archival failures. Public interfaces have type annotations; `py.typed` marks the installed package.

`archives.py` detects signatures and owns a ZIP or RAR handle per worker. Metadata inspection precedes page discovery. It validates all member names, sizes, compression ratios, encryption and link policies, including non-image entries. ZIP central-directory limits are checked before ZipFile allocates its member records. RAR callbacks limit header enumeration during parsing. Readers stream selected entries; no archive pathname is ever passed to filesystem extraction. Actual page reads check size and reach EOF for backend CRC checks. `rar_backend.py` isolates a correction to rarfile 4.2 and 4.5 bsdtar argument ordering, using the library's seekable checksum-checking pipe reader without extraction or global patches. Literal member selectors escape bsdtar glob syntax. Solid RAR4 is refused explicitly with bsdtar because that decoder cannot support it; UnRAR/7-Zip pass those fixtures.

`ordering.py` produces locale-independent keys from NFC paths, treating backslashes as separators. Directory components compare before children. ASCII numeric runs compare as integers; equal numbers use fewer leading zeros first. Text compares case-insensitively, then original spelling breaks ties. Normalized duplicate paths are rejected; case ambiguities are reported. `--ordering lexical` is an explicit compatibility alternative.

`images.py` inspects format, dimensions, modes, frames, ICC presence and orientation. `png.py` uses Pillow's chunk parser to collect complete PNG metadata without constructing a raster, retaining chunk CRCs and text/ICC decompression guards. Opaque non-interlaced data also receives bounded native DEFLATE, scanline-size and filter-tag validation; animation/interlace/alpha paths retain Pillow decoding where needed. It retains no full list of decoded images. img2pdf requests each `ImageInput.read()` lazily. Ordinary JPEG/PNG data passes directly; normalization uses one decoded frame at a time. Multiframe members alone are staged under generated application-owned names to avoid repeated archive decompression. Frames expand in member order, followed by frame index.

Mirrored EXIF orientations require pixel normalization; ordinary rotations can use PDF rotation while retaining JPEG streams. Fixed-page layout normalizes orientation to honor the requested displayed page dimensions. Indexed resizing converts to RGB/RGBA before Lanczos sampling. Native DPI and ICC profiles are carried through normalization where compatible. CMYK JPEGs remain CMYK by default; lossy CMYK-to-RGB conversion uses the embedded ICC profile when present. Float/32-bit integer TIFF samples are refused rather than silently quantized.

`pdf.py` uses img2pdf's internal engine and its document's `tostream()` serializer, avoiding a second complete PDF byte string. The library retains compressed document objects until finalization. The adapter owns its internal-engine document handle: it applies previously inspected per-page rotations, serializes normally, then breaks the Parent/Kids ownership cycles and clears object references before starting verification. This avoids waiting for Python's garbage collector and is covered by real-output tests with automatic GC disabled. This is not constant-memory conversion. Independent strict pypdf verification checks finalization, page counts, content, dimensions and image resources. Direct JPEG and compatible PNG IDAT streams have per-page SHA-256 verification, which also detects swapped pages with equal dimensions. Verification checks the expected page rotation too, uses read-only mapping only for documents up to 16 MiB (falling back to ordinary reads if mapping is unavailable), and closes its reader explicitly. It does not render all pages or fully decode every JPEG by default.

`transactions.py` exclusively creates an owned destination-filesystem temporary, syncs it, and publishes using a hard link or explicit replacement. Commit state becomes true as soon as the destination exists; a subsequent directory-sync failure is reported as committed with incomplete durability. Archival is a separate copy-first transaction followed by unlinking the original name. Source fingerprints catch ordinary concurrent mutations. This assumes user-controlled source/output directories, not a hostile process concurrently replacing filesystem entries.

`converter.py` sequences these stages and returns truthful results. A complete success requires verification and commit, plus source archival when requested. Controlled input/library/filesystem errors become failed result objects. Programming errors and KeyboardInterrupt propagate. `scheduler.py` keeps at most the effective worker count of futures active, uses paths rather than image payloads in its queue, and cancels cooperatively between reads and before publication. One worker is the conservative default. Thread scaling is measured; multiprocessing is not implemented or claimed to be superior/inferior without an equivalent experiment.

`reporting.py` configures console/exclusive file logs and exclusive atomic JSON reports. `cli.py` owns argument parsing, preflight destination checks, progress and exit codes. `benchmark.py` provides the installed self-benchmark; repository runners add historical comparisons and private PDF-derived real-content fixtures.

`digests.py` owns one optional hashing worker per active stage and at most two queued/running payloads. Payloads under 256 KiB are hashed inline; larger SHA-256 work can overlap the next member read or PDF parsing. Writer and verifier stages are sequential, so a converting archive has at most one hashing helper at a time. Every future is resolved and exceptions propagate before commit. Completed image futures retain digest strings, not copies of page data. Neither raster caches nor process-global monkey patches are used.

The PNG adapter and internal PDF document-handle usage are intentionally isolated library integration points. The release tests cover Pillow 10.4.0/13.0.0, img2pdf 0.6.3, pypdf 6.12.0/6.21.4 and rarfile 4.2/4.5 on Linux. The rarfile PipeReader/parser interface is an additional isolated integration point. Other platforms remain a CI gate.

The RAR adapter also inspects enabled 7-Zip compression methods once per compressed archive, with a ten-second subprocess timeout. Archive-format handlers alone do not establish decoder availability. It distinguishes a missing native codec from a corrupt member without disabling CRC/size checks or mutating process-global library state.
